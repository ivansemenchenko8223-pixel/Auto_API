# Auto API

REST API для учёта автозапчастей и заказов на **FastAPI + SQLAlchemy + SQLite**.

Что умеет:

- регистрация и вход пользователей (JWT-токен);
- каталог деталей: список, поиск по артикулу, добавление (только администратор);
- оформление заказа с проверкой и списанием остатков на складе.

---

## 1. Что нужно установить заранее

**Python 3.11 или новее.** Проверьте, что он есть:

```powershell
python --version
```

Если команда не найдена — скачайте с https://www.python.org/downloads/ и при установке
поставьте галочку **«Add Python to PATH»**. Если у вас несколько версий Python,
вместо `python` используйте `py -3.11`.

Всё остальное (FastAPI, сервер и т.д.) ставится автоматически на шаге 3.

---

## 2. Скачать проект

Если проект уже лежит у вас в папке — просто откройте её в терминале
(PowerShell). Иначе:

```powershell
git clone <адрес-репозитория> Auto_API
cd Auto_API
```

Дальше все команды выполняются **из папки `Auto_API`**.

---

## 3. Создать виртуальное окружение и поставить зависимости

Виртуальное окружение (venv) — это отдельная папка с библиотеками только для
этого проекта, чтобы не засорять систему.

```powershell
python -m venv venv
```

Активировать его (делать при каждом новом запуске терминала):

```powershell
.\venv\Scripts\Activate.ps1
```

После активации в начале строки появится `(venv)`.

> Если PowerShell пишет `выполнение сценариев отключено в этой системе` —
> один раз выполните:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
> и снова активируйте окружение.

Установить библиотеки:

```powershell
pip install -r requirements.txt
```

---

## 4. Создать файл настроек `.env`

В проекте есть шаблон `.env.example`. Скопируйте его в `.env`:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в любом редакторе. Обязательно заполните `SECRET_KEY` —
это секретная строка для подписи токенов. Сгенерировать её:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте вывод в `.env`, чтобы получилось примерно так:

```
DATABASE_URL=sqlite:///./detal.db
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
SECRET_KEY=сюда-вставьте-сгенерированную-строку
```

| Переменная | Зачем нужна |
|---|---|
| `DATABASE_URL` | где хранится база. По умолчанию файл `detal.db` рядом с проектом |
| `SECRET_KEY` | секрет для подписи JWT. **Без него сервер не запустится** |
| `JWT_ALGORITHM` | алгоритм подписи токена, оставьте `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | сколько минут живёт токен после входа |

---

## 5. Запустить сервер

```powershell
uvicorn app.main:app --reload
```

Если всё хорошо, увидите строку `Uvicorn running on http://127.0.0.1:8000`.
База данных `detal.db` создастся сама при первом запуске.

Остановить сервер — `Ctrl + C` в терминале.

---

## 6. Открыть и попробовать API

Откройте в браузере: **http://127.0.0.1:8000/docs**

Это интерактивная документация (Swagger). Здесь можно нажимать на запросы,
жать «Try it out», вводить данные и «Execute».

### Порядок действий

**1) Регистрация** — `POST /api/v1/auth/register`

Тело запроса:

```json
{
  "email": "user@example.com",
  "phone_number": "89161234567",
  "username": "user1",
  "password": "MyPass123!"
}
```

Правила: `phone_number` — ровно 11 цифр без пробелов и знаков;
`username` — 2–20 символов; `password` — 8–20 символов.

**2) Вход** — `POST /api/v1/auth/login`

Отправляется как **форма** (в Swagger просто заполните поля `username` и
`password`). В ответе придёт `access_token`.

**3) Авторизоваться в Swagger.** Нажмите кнопку **Authorize** вверху страницы,
вставьте полученный `access_token`, подтвердите. Теперь защищённые запросы
будут работать.

**4) Создать заказ** — `POST /api/v1/orders/order`

```json
{
  "items": [
    { "detal_id": 1, "quantity": 2 }
  ]
}
```

Заказ пройдёт, только если деталь с таким `id` есть в базе и на складе
хватает количества.

### Список эндпоинтов

| Метод и путь | Что делает | Нужен вход |
|---|---|---|
| `POST /api/v1/auth/register` | регистрация | нет |
| `POST /api/v1/auth/login` | вход, выдаёт токен | нет |
| `GET /api/v1/detals/get_all_detal_from_db` | список деталей | нет |
| `GET /api/v1/detals/get_detal_by_article` | поиск детали по артикулу | нет |
| `POST /api/v1/detals/create_new_detal` | добавить деталь | да, **админ** |
| `POST /api/v1/orders/order` | создать заказ | да |

## 7. Как стать администратором

Добавлять детали может только пользователь с признаком администратора.
Сразу после регистрации его нет. Проще всего выдать права через базу.

Установите один раз утилиту для просмотра БД или используйте Python:

```powershell
python -c "import sqlite3; c=sqlite3.connect('detal.db'); c.execute(\"UPDATE users SET is_admin=1 WHERE username='user1'\"); c.commit(); print('готово')"
```

Замените `user1` на свой `username`. После этого снова войдите
(`/auth/login`), получите новый токен — и `create_new_detal` заработает.

## 8. Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `RuntimeError: SECRET_KEY не задан` | не заполнен `SECRET_KEY` в `.env` (шаг 4) |
| `command not found: uvicorn` / `python` | не активировано окружение — выполните `.\venv\Scripts\Activate.ps1` |
| `выполнение сценариев отключено` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, затем активируйте venv заново |
| `Address already in use` / порт занят | запустите на другом порту: `uvicorn app.main:app --reload --port 8001` |
| `no such column: users.is_admin` и т.п. | старая база не совпадает с новыми моделями — см. раздел 9 |
| `401 Unauthorized` в защищённом запросе | не нажали **Authorize** в Swagger или истёк токен — войдите заново |
| `403` при добавлении детали | у пользователя нет прав администратора — см. раздел 7 |

## 9. Сбросить базу данных

Схема БД создаётся автоматически при старте, но **не обновляется**, если файл
`detal.db` уже существует со старой структурой. Если меняли модели или видите
ошибки про отсутствующие колонки — удалите базу и запустите сервер снова:

```powershell
Remove-Item detal.db
uvicorn app.main:app --reload
```

Все данные при этом теряются.

---

## 10. Ручные проверки

`test.py` и `test_ai.py` — простые скрипты, которые дёргают уже запущенный
сервер. Сначала запустите сервер (раздел 5), потом в другом терминале
(с активированным venv):

```powershell
python test.py
```

Проверьте адрес `BASE_URL` в начале файла — он должен совпадать с портом сервера.
